# P3b Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The squad remembers what happens to it, and the main model is told, within a budget the player sets:
- engine events (runs, combat, votes, scapegoat, dilemmas, discipline, P9c pressure) become facts with the right audience, and the rest of the squad hears them later as rumors;
- old facts are folded into a per-unit dossier instead of being deleted;
- the relation journal, a short "recently in the unit" chronicle and a recap of recent DMs reach the prompt;
- long scenes are summarized whole; old scenes can be hidden from the ST chat;
- memory has presets, its own token share, a fill indicator and a MEMORY view (pin / forget; edit with the edit lock off);
- a fact can be hidden from the commander (for P12).

**Architecture:**
- **Engine.** `src/engine/memory.ts` becomes the folder `src/engine/memory/`:
  - `index.ts` re-exports everything `memory.ts` exported (no import elsewhere changes);
  - new files: `config.ts`, `remember.ts`, `resolvers.ts`, `rumors.ts`, `fold.ts`, `audience.ts`, `journal.ts`.

  The engine stays pure. Rumor spread uses a string hash, never the RNG.
- **Hook points.**
  - `dispatch` calls `rememberEvents` after a successful handler.
  - The day end gets a `rumors` step.
  - `scene/end` and `compactionDue` read audiences.
  - New actions: `memory/configure`, `memory/fold`, `memory/pin`, `memory/forget`, `memory/edit`, `memory/edit_dossier`, `scene/digest`.
- **LLM and context.**
  - `ContextBuilder` gets provider groups and a guaranteed `memory` share.
  - New providers live in `src/scene/memoryContext.ts`.
  - New call types: `memory_fold`, `rumor_retell`, and the `digest` mode of `scene_summary`.
  - One controller, `src/scene/memoryController.ts`, runs the fold, the rumor retelling, the digest and scene hiding, the way `runCompaction` does.
- **ST.** The adapter gets `hideMessages` / `unhideMessages` (ST `/hide`, `/unhide`).
- **UI.**
  - SYS › MEMORY: presets, numbers and the fill indicator.
  - A MEMORY block in each unit's dossier (SQUAD tab) and a world MEMORY block in SYS.
  - Glossary entries and an analysis provider.
- **Chunks.**
  - **Chunk (a), Tasks 1–8:** the engine.
  - **Chunk (b), Tasks 9–12:** context and LLM.
  - **Chunk (c), Tasks 13–16:** ST, UI and docs.

**Tech Stack:** TypeScript 5 (strict), esbuild, zod 3, vitest (+ jsdom for UI). No new dependencies.

## Global Constraints

- **English and safe text.** Everything is in English. UI text goes through `h()` / `textContent`, never `innerHTML`.
- **Engine purity.**
  - `src/engine/**` stays pure (`tests/architecture.test.ts`).
  - `src/engine/memory/` imports no UI, `llm` or `st`.
  - `power/state.ts` and `personal/state.ts` stay leaves; memory never imports them for anything but types.
- **The engine decides** (P1–P3).
  - Which event is remembered, who knows it, when a rumor spreads and what is folded are engine computations.
  - Models only word (fold, retelling, digest) and never write numbers.
  - P3b adds **no new intent** and does not change the `intent_extract` input.
- **No new RNG draw (spec acceptance 7).** Rumor timing is `hashDay(factId, unitId)` (FNV-1a over the string). Every seeded test from before P3b must keep its RNG state. A change that moves a seeded test **stops and reports**.
- **Privacy per audience** (spec Principles). Nothing private reaches a shared prompt:
  - facts: every present unit knows it, as today;
  - chronicle: the audience includes every present unit;
  - dossier `own`: private scene or DM only;
  - journal evidence: private scene only;
  - DM recap: private scene only.
- **Squad secrets stay P9c's.** Nothing reads `personal.secrets[].text`. A kept secret never becomes a `Fact` through a memory rule.
- **Read by field, never by id.**
  - Rules are read by `event` and `when`.
  - Resolvers are keyed by event type: a closed vocabulary, like intent types.
  - No code tests a rule id, a template id or an option id.
- **Spec numbers.** These are the preset table (§1), the rule table (§2.1, texts `AUTHOR TO WRITE`) and these drafts:
  - dossier caps: `own` 500 chars, `shared` 400;
  - fold batch: 6;
  - digest threshold: 2500 tokens, keeping the last 4 messages;
  - rumor windows: fast 2 days, slow 4, halved at importance ≥ 4;
  - pinned retrieval bonus: +2;
  - hard ceiling: `factsMax × 1.25`;
  - new default `contextTokenCap`: 1600.
- **Ids.**
  - Directive ids: none new.
  - Glossary ids: `memory`, `memory_fill`, `memory_preset`, `memory_budget`, `dossier`, `rumor`, `pinned_fact`, `hidden_scenes`.
  - Call type ids: `memory_fold`, `rumor_retell`.
- **Text.**
  - No pronoun for the commander in any text (lore §0); `tests/content/pronouns.test.ts` must pass.
  - Every new chip, card, stat and option carries `data-analyze` and has a glossary entry.
- **Old saves.**
  - Every new field is optional and the version stays 1.
  - Absent `memory.config` reads as `normal`.
  - A chronicle entry without `audience` is LOG-only.
  - A fact without the new fields reads as unpinned, seen and known to the commander.

## Where the plan rules on the spec (read before Task 1)

Rulings marked **(user)** were answered by the user on 2026-11-16. Task 16 copies all of them into the spec's **Implemented as**.

- **What is remembered (user).** All four groups:
  - runs and combat;
  - power decisions: votes, scapegoat, leader, countermand, rations;
  - discipline and dilemmas;
  - P9c personal pressure.

  The rule list of spec §2.1 is exhaustive for v1. Sites that already write a fact get no rule.
- **Who learns (user).** Witnesses know at once; the rest hear it as a rumor over 1–2 days. Spread is deterministic.
- **Rumor mode (user).** Both modes, switched in the settings:
  - default `plain`, with no mechanic call;
  - `model`: the mechanic retells the rumor once per fact.
- **Forgetting (user).** Old facts are folded into a per-unit dossier by the mechanic. Folding runs **on fill** (spec §5 `foldDue`), not on a schedule. The number of facts kept is a setting, and fill is shown.
- **Settings (user).** Presets plus fields. The fields are editable only with the **edit lock off** (`editLock`, existing setting). No new "advanced" switch.
- **Memory UI (user).**
  - Normal mode: view, pin and forget.
  - Edit lock off: also edit fact text, the dossier and the numbers.
- **Journal in the prompt (user).** Directly, per present unit: the last `journalLines` events of kind `event` with severity ≥ `moderate`, plus any severity from the last 2 days. Evidence in a private scene only; in a group scene, types and days only.
- **Chronicle in the prompt (user).** "Recently in the unit": the last `chronicleDays` days plus the newest 1–2 week entries, filtered by audience. It reaches scenes, the block outside a scene (public only) and `director_tick`.
- **DMs (user).** A recap of recent DMs goes into a **private** scene with her. DM fact extraction stays as it is. `dm_reply` gets her dossier and journal (spec §6, "Other calls").
- **Hidden from the commander (user).** Lay it down now: `Fact.hiddenFromCommander`, a Knowledge rule, the prompt wording. v1 core rules create none.
- **Extras (user).** All four are in v1:
  - long scenes summarized whole (digest);
  - hiding old scenes in ST, off by default;
  - memory's own budget inside the cap;
  - memory in calls outside a scene.
- **Order (user).** P3b comes before P10b. It is inserted in the §9 table and in `ROADMAP-next.md`.
- **`contextTokenCap` default 1200 → 1600.** Only the default changes. A value the player stored stays. SYS shows a warning when `memoryTokens > contextTokenCap / 2`.
- **`memory.ts` → `memory/` folder.** `index.ts` keeps every old export, so no importer changes. Tests import from `src/engine/memory` as before.
- **Dossier privacy.** The fold splits facts:
  - **shared**: `knownBy` includes `'*'`, or every living named unit;
  - **own**: the rest.

  Hidden-from-commander facts are never folded; they wait for P12.
- **Fold without a profile.** `fallbackFold` adds the new facts' texts after the current dossier part and cuts from the **front**, so the oldest text goes first.
- **Remembered facts in a rolled-back action.** They are written in the same draft, so a rejected action, a swipe rollback or an easy-mode rewind takes them along. No extra code.
- **Expedition combat.** Combat inside a run is remembered through `expedition_ended`, `breakdown` and `order_refused`. `combat_ended` has no rule; the protect and endanger hints are already journal entries.
- **Out-of-scene block.** World settings, as today, plus the world dossier `shared` and the public `recent` lines.
- **Scene hiding.**
  - It needs the scene's summary to have been stored, which the action `scene/end` with a summary records as `memory.summarized[sceneId]` (bounded to the last 50).
  - Ranges come from `scene.startIndex` up to the next scene's `startIndex − 1`, so the scene record must store its end index: `ChronicleEntry.range?: [from, to]` on the scene line.
  - The slash command is `/hide from-to` (and `/unhide`).
- **Digest and swipes.** The digest stops 4 messages before the end. A swipe never reaches it. An edit of an older message does not redo it (documented in the manual test).
