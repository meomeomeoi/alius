# P5 — World Map, Expeditions, Missions & Director

**Depends on:** P0–P4. **Read:** overview; `content/lore.md` (§3, §4, §6, §7).

## Goal

The world moves: a world map with regions, a mission board fed by command and by the story, rumors in the PDA, expeditions as node-map runs, and a director that steers authored spine beats, threads and clocks from world state and the player's decisions.

## 1. World state

- `clocks[]`: `{ id, label, segments, filled, regionId?, onFill: effectIds, visibleToPlayer }` (e.g. Bloom spread in a region, rival corp operation, oversight suspicion).
- `threads[]`: `{ id, title, status: 'open'|'resolved'|'failed'|'dormant', flags[], relatedUnits[], relatedRegions[], createdDay }`.
- `factions`: standing −100…100 per corporation/faction.
- `flags[]`: consequence flags from decisions (`delivered_evidence_vesper`, `spared_survivors_k12`…).
- `spineProgress`: current beat index + beat states for the chosen start.
- `clearanceTier`: raises level caps (P4); granted by spine beats and certain missions.

## 2. World map (MAP tab)

- Author-supplied image (`content/core/map/world.png`) with region hotspots (polygons in `regions`). Fallback: ASCII region map.
- Region panel: environment, danger, known enemy categories, active clocks, available missions, points of interest.
- Selecting a mission/POI opens the expedition planner.

## 3. Missions (OPS tab)

- Mission: `{ id, source: 'command'|'story'|'rumor'|'side', title, brief, regionId, danger, objective (node type + condition), deadlineDay?, rewards {credits, plyx, items, clearance?, faction}, failureEffects, threadId?, spineBeat? }`.
- Deadlines are generous (default ≥ 5 days); command missions failing affect oversight/faction standing and Leash authorizations (P6).
- Rumors: short BBS-style posts (`RUMOR MILL` board look) that can convert to side missions or facts; generated by the director, more with Comms level and Insight.
- Board size limited by Comms level.

## 4. Expeditions

- Planner: choose up to 4 units (+ formation rows), loadout check, supplies to bring (rest nodes consume), duration estimate (2 or 3 slots).
- **Node map** generated from region template + mission: 3–5 layers, 2–3 nodes per layer, branching edges; node types (`nodeTypes` registry): `combat, elite, event, cache, rest, unknown, objective, crisis` (crisis = Commander Crisis combat). Fog: only adjacent nodes revealed (Echo Bleed / scouting reveal more).
- ASCII rendering: `[⚔]──[?]──[≡]` style with path highlight.
- Event nodes: from `dilemmaTemplates` with `scale: 'minor'` (P6 provides the full dilemma system; P5 ships simple fixed-option events with costs) or flavor-only.
- Between nodes: swap rows, use consumables, check stress.
- Retreat any time (lose unbanked loot).
- Return: resources banked, `expedition_recap` (main model, optional by setting) generated from the structured combat/event log, shown as an "AFTER-ACTION REPORT"; then P3 receives expedition intents (`protected`, `endangered`, `sided_with/against` from event choices) and the debrief hook (optional scene with any unit).

## 5. Director (`director_tick`, mechanic profile)

Runs at day end (P2 pipeline) and after expeditions. Engine assembles a compact world digest: day, spine beat + its goal, open threads, clocks, faction standings, recent major flags, squad relationship highlights (states only), mission board.

Output schema:
```
{
  missionOffers: [{ templateId, regionId, danger, title, brief, objectiveNode, deadlineDays, rewardsTier, threadId?, spineBeat? }] (≤2),
  rumors: [{ text (≤40 words), leadsTo?: 'mission'|'fact'|'none', tags[] }] (≤3),
  threadUpdates: [{ threadId|'new', title?, status?, addFlags?[] }],
  clockAdvances: [{ clockId, by: 1|2, reason }],
  storyBeatProposal?: { beatId, framing (≤60 words) }
}
```
Engine validation: ids exist, rewards come from tier tables (the model never sets amounts), max clock advance per tick, spine beats only when beat conditions are satisfied, at most one story-beat proposal per 3 days (setting). Rejected parts are dropped silently (debug log).

**Spine:** each start has 5–8 authored beats with `conditions` (flags, days, clearance, thread states) and `goal`. The director chooses *when* and *how* to frame them (mission, rumor, incoming unit, event), never skips or invents spine beats. After the last beat, the director runs open-ended from clocks/threads/factions.

**Incoming named units:** a story/mission outcome can offer "new unit available"; the player imports a card via the short P1 wizard (or declines; a grunt joins instead).

## 6. Context contribution

Provider adds 1–3 sentences of world state relevant to the scene (region of last expedition, active thread involving present units, clocks above 50%).

## Acceptance criteria
1. Map shows regions (image or ASCII), missions per region, clocks.
2. Missions from command, story, rumor and side sources appear; deadlines tick; failure effects apply.
3. An expedition from planner to return works with combat, event, cache, rest and objective nodes; retreat works; loot banked.
4. After-action report generated from the structured log; P3 intents from the expedition applied.
5. Director output with invalid ids/amounts never mutates state; spine beats only fire when conditions hold; open-ended phase continues after the spine.
6. Clearance tier raises the level cap.
7. Tests: node map generation (seeded), digest builder, director validation, clocks, deadlines.
