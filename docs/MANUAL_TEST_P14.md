# P14 — acceptance checklist (generation envelope)

Automated coverage per acceptance criterion (all in `npm test`), then the steps that must be done by hand inside SillyTavern. The automated tests use fake models and jsdom: they cannot judge a real provider's refusal, stop reason or timeout, nor how the chips look.

## Automated
1. **Every failure reason is classified from recorded fixtures** (refusal text, cut JSON, length stop, timeout, invalid schema, empty, thrown error): `tests/llm/classify.test.ts`, `tests/st/finishReason.test.ts`, `tests/fixtures/llm/failures.ts`.
2. **Every call site runs through `generate`; the architecture test fails on a direct `callLlm` import:** `tests/architecture.test.ts`, `tests/llm/siteRegistry.test.ts` (every call type and every flavor kind has a site).
3. **A failure leaves a record and a chip at its surface and in SYS; RETRY rebuilds the input, applies on success and closes the record; an expired record says why:** `tests/llm/envelope.test.ts`, `tests/llm/envelopeFixtures.test.ts` (six reasons × `expedition.recap`, `dilemma.generate`, `scene.summary`, `director.tick`), the per-site tests (`tests/scene/generationSites.test.ts`, `commsGeneration.test.ts`, `backgroundGeneration.test.ts`, `tests/world/directorController.test.ts`, `recapGeneration.test.ts`, `tests/loyalty/dilemmaGeneration.test.ts`, `tests/discipline/demandGeneration.test.ts`, `tests/bonds/ruleGeneration.test.ts`, `tests/warden/wardenGeneration.test.ts`, `tests/setup/importGeneration.test.ts`), `tests/ui/generationChip.test.ts`, `tests/ui/generationSurfaces.test.ts`, `tests/ui/generationsSys.test.ts`.
4. **Fallbacks still apply; a later success replaces them per the site's mode:** the same per-site tests (`fallbackApplied`, `dilemma/reword`, `scene/late_summary`, `campaign/epilogue { replace }`).
5. **REROLL works per mode; `revert` restores and reapplies only while nothing changed, else it is disabled with a reason:** `tests/llm/envelopeFixtures.test.ts` (`revert refused when the state moved`), `tests/ui/generationSurfaces.test.ts`, the per-site reroll tests.
6. **State stays small; no prompt, transcript or raw output is stored:** `tests/engine/generations.test.ts` (cap 20, detail cut to 160), `tests/llm/envelopeFixtures.test.ts` (`state stays small`, `no prompt, transcript or model text appears in the records`).
7. **Every new chip, button and list row carries `data-analyze`:** `tests/ui/generationChip.test.ts`, `tests/ui/generationSurfaces.test.ts`, `tests/ui/analyzeCoverage.test.ts`; hidden values never reach a reading or a label (`tests/analysis/hidden.test.ts`, the sentinel check in `generationChip.test.ts`).
8. **Seeded runs do not move:** `tests/warden/unaffected.test.ts`, `tests/special/unaffected.test.ts` and every `unaffectedWeek` user are unchanged.
9. **Old saves:** `generations` is optional and `version` stays 1 (`tests/engine/generations.test.ts`).

## In SillyTavern
Note the SillyTavern version, the connection profiles (API and model) and the browser at the top of your report. Use a fresh chat for each part. Open SYS › Generation first: the timeout is 120 s and automatic retries are 1 by default.

- [ ] **A refusing mechanic profile — a scene reading.** Pick a mechanic profile whose model refuses (or answers "As an AI I cannot…" to the reader's prompt). Talk in a scene: under the transcript a chip reads `Scene reading: the model refused.` with `[RETRY]` and `[⋯]`; one record per unread chunk, not one per exchange; the scene itself keeps working. A warn toast appears once (outside debug mode too). Switch to a working profile and press `[RETRY]`: the chip goes and the relationship change is applied.
- [ ] **A refusing profile — a dilemma.** Let a decision be generated: the authored block shows at once with the chip `Decision text: the model refused.`; `[RETRY]` rewords it while it is unanswered; once you answer, REROLL is disabled and says `It was answered.`.
- [ ] **A refusing profile — a recap.** End an expedition with the recap setting on: the report shows the deterministic lines and `After-action recap: the model refused.`; `[RETRY]` or `[⋯]` › main model writes it; afterwards `[REROLL]` replaces it.
- [ ] **A tiny budget (truncated).** Set the `scene_summary` budget (SYS › Output budgets) to 20 and the request floor to 0: end a scene. The chip says `the answer was cut off at <n> tokens` (the number is the budget times the retry multiplier). `[⋯]` › ×3 retries with the bigger budget. Restore the budgets afterwards.
- [ ] **A timeout.** Set the model timeout to 10 s and use a slow model (or throttle the connection): the call is abandoned at 10 s, the chip says `no answer within 10 s`; a main-model answer that arrives late is ignored (with debug on, its row in SYS › GENERATIONS and the log mark it late).
- [ ] **A dead connection.** Disconnect the API (or stop the backend): the chip says `the connection failed`; reconnect and `[RETRY]`. Nothing in the campaign changed while it was down.
- [ ] **RETRY with ×2 and the main profile.** `[⋯]` offers ×1.5 / ×2 / ×3 and, only with a mechanic profile selected, MAIN / MECHANIC; the menu choice is what the next call uses (check the request in the browser's network tab or the debug log). With no mechanic profile selected the profile row is not there.
- [ ] **USE FALLBACK on the director.** Make the director's call fail (refusing profile): the request stays open (the day's plan is not made), the hub FAILED block and SYS list it with `[USE FALLBACK]`. `[USE FALLBACK]` plans the world with the engine's plan; or end the day instead: the engine plans it and the record turns to `The day ended: the engine planned the world.` for a day.
- [ ] **A late scene summary.** Make the summary fail, end the scene (it ends with a plain one-line summary), play on for a day or two, then `[RETRY]` it from the hub FAILED block or SYS: the plain line of that scene is replaced and its facts are added once. A scene summarized by a compaction in between only gets facts.
- [ ] **REROLL of a DM.** After her reply, `[REROLL]` sits under it: it restores the state from before her reply, asks again and reads the new one; after another action (read a message, end a slot) it is disabled and says `Something happened since: this can no longer be rerolled.`.
- [ ] **REROLL of a dilemma, a recap and the last scene.** The dilemma card (before an answer), the report (always) and the hub's `LAST SCENE` line (while nothing else happened) each replace their result; a failed reroll keeps what was there.
- [ ] **The disabled REROLL reason.** Hover or long-press (analysis) a disabled `[REROLL]`: the title and the analysis panel give the reason; it never throws.
- [ ] **SYS › GENERATIONS, the badge and the hub line.** The list shows open and expired records, newest first, with `[RETRY]`, `[⋯]` and `[DROP]`; background records (a name, a rumor, a vignette) are listed as `background` and do not count on the SYS tab badge or in the hub line `N generations failed.`; with no mechanic profile and no fallback to the main model one standing line says so. In debug mode a row shows the raw answer; without debug it does not.
- [ ] **The settings.** SYS › Generation: the timeout accepts 10–600 s and the retries 0–2 (anything else snaps back); with 0 retries a truncated answer shows its chip at once.
- [ ] **Metadata size.** After many failures (a refusing profile for a long scene) the chat metadata did not grow: at most 20 records, no text from the model.
- [ ] **Old save.** Load a campaign saved before P14: it opens, `generations` is absent and nothing is listed.
